# 05 · 开源方案清单：传统分层栈 vs VLN / VLA 导航

> 核实时间：**2026-11-23**，全部通过 GitHub API 实查（star / 最后 push / license）。
> 本文只列**能真的 clone 下来跑**的仓库，不列只有论文没有代码的工作。

---

## 0. 一句话结论

- **传统分层栈的开源成熟度是「拼装级」**：每一层都有 1-2 个事实标准仓库，但没有一个仓库覆盖全栈。你要做的是选型 + 写胶水。
- **VLN 的开源成熟度是「基准级」**：仿真评测（Habitat + VLN-CE）配套完整，但真机闭环需要自己补运控与安全层。
- **四足上真机跑通的 VLN 开源项目，目前只有 NaVILA 一个。**

### 1.4 一套可以照着搭的组合

```
robot_localization（EKF 融合）
  + 腿里程计（自写，200–1000 Hz）
  + elevation_mapping_cupy（有 GPU）或 grid_map（纯 CPU）
  + Nav2（MPPI + STVL + 自定义 costmap 层）
  + 自研运控（IsaacLab 训的 RL 策略）
```

这套是**目前唯一能在四足上稳定复现的组合**，也是本调研报告第 2 章给的建议路线。

## 3. 两条路线对比

| 维度 | 传统分层栈 | VLN / VLA |
|---|---|---|
| 开源完整度 | 每层都有，需自己拼 | 端到端代码完整，但只覆盖「决策」 |
| 真机可用性 | 高（工业界在用） | 低（除 NaVILA 外基本是仿真/室内） |
| 可解释性 | 高（每层可查） | 低（黑盒输出动作） |
| 数据需求 | 无（几何+规划） | 大（百万级轨迹或视频） |
| 改造成本 | 低（换参数/换插件） | 高（要重训） |
| 失败模式 | 建图漂移、规划卡死 | 指令理解错、长程误差累积 |
| 适合场景 | 巡检、已知环境、要交付 | 科研、开放词汇、长程任务 |

**结论**：**产品走分层，研究走 VLN**。两者不是替代关系——NaVILA 本身就是「VLM 出高层指令 + RL 运控执行」的分层结构，只是把「导航规划」换成了 VLM。

## 4. 三种场景的组合建议

**A. 要做巡检产品**
```
robot_localization + elevation_mapping_cupy + Nav2(MPPI+STVL) + 自研 RL 运控
```
不碰 VLN。

**B. 要做「说一句话就去找东西」的 demo**
```
NaVILA 或 Open-Nav（零样本） + Nav2 做底层避障 + 自研运控
```
NaVILA 是唯一有四足真机验证的选项。

**C. 要做研究，找空白**
```
Habitat + VLN-CE 做评测基线 → StreamVLN / InstructNav 做方法改进
```
真机验证阶段再补运控。

## 5. 四条注意事项

1. **star 数 ≠ 四足适配度。** `navigation2` 5.1k star，但默认配置在四足上就是「跑得很快的轮式机器人」——footprint、分辨率、控制频率三处必须改。
2. **停更的仓库不要碰。** `VINS-Fusion`（2024-05）、`elevation_mapping`（2024-11）、`visualnav-transformer`（2024-09）、`VLN-CE`（2025-01）都已停更，能跑但不该进新产品。
3. **许可证要提前看。** FAST-LIO / VINS-Fusion / OpenVINS 是 **GPL**，商用要注意；Nav2 是 Apache/BSD 系相对宽松；StreamVLN、InstructNav 未声明许可证，商用前必须问作者。
4. **VLN 的开源项目多数只出「高层指令」，不出关节力矩。** 接到四足上必须自己补：指令 → 速度 → RL 策略 → 关节，这一段没有任何开源项目替你做完。
