# 00 · 总览：四足全栈的五层结构与 2023-2026 演进

> 本章是整份调研的骨架。读完后你应该能回答三个问题：
> ① 一只机器狗的算法栈到底分几层、每层跑什么频率；
> ② 这几年范式怎么变的；
> ③ 2026 年「宣传」和「真机跑通」之间的差距在哪。

---

## 1. 一句话结论

**四足机器狗的算法栈已经收敛成五层「金字塔」：底层是本体与传感器（硬件厂提供），往上依次是状态估计、地形感知/建图、导航规划、运动控制，顶层是任务理解。2021 年以后，中间的运动控制层被 RL 彻底改写；2025 年以后，顶层的 VLA/世界模型开始往下压——但真正常态化跑在真机上的，仍然只有下面四层。**

换句话说：

- **下面四层是工程问题**，有成熟方案、有开源实现、有明确的性能指标；
- **顶层是研究问题**，demo 惊艳、复现困难、离产品交付还有距离。

这条判断贯穿整份报告，也是我们拒绝把「四足 + VLA」当成既定事实来写的原因。

## 2. 五层结构

### 2.1 分层总表

| 层 | 职责 | 典型频率 | 典型算力 | 成熟度 | 归属 |
|---|---|---|---|---|---|
| **L5 任务理解** | 自然语言指令 → 任务分解 → 技能调用 | 0.2-2 Hz（事件驱动） | 边缘 GPU / 云端大模型 | 🟡 研究阶段 | 算法团队 |
| **L4 导航规划** | 全局路径、局部避障、可通行性 | 10-50 Hz | CPU 单核-四核 | 🟢 成熟 | 算法团队 |
| **L3 地形感知** | 高程图/点云、落脚点评估 | 10-30 Hz | CPU+GPU（可选） | 🟢 成熟 | 算法团队 |
| **L2 状态估计** | 机身位姿、速度、接触状态 | 200-1000 Hz | CPU 单核 | 🟢 成熟 | 算法/固件团队 |
| **L1 运动控制** | 关节力矩/位置指令，保持平衡与步态 | 50-500 Hz | CPU 单核 或 小型 NPU | 🟢 高度成熟 | 运控团队 |
| **L0 本体** | 电机、IMU、关节编码器、足端力传感 | 1-10 kHz（驱动器内环） | MCU | 🟢 商品化 | 硬件厂 |

> 频率是量级，不是精确值。不同厂商差一个数量级很常见（例如有的厂把状态估计和控制合并跑在 500 Hz）。

### 2.2 数据流（自下而上）

```
                     ┌─────────────────────────────┐
   L5 任务理解  ←──  │ 语言/视觉指令 → 技能序列      │  0.2-2 Hz
                     └──────────────┬──────────────┘
                                    │ 目标点 / 技能 ID / 速度指令
                     ┌──────────────▼──────────────┐
   L4 导航规划  ←──  │ 全局规划 + 局部规划 + costmap │  10-50 Hz
                     └──────────────┬──────────────┘
                                    │ 速度指令 (vx, vy, ωz) / 落脚区域
                     ┌──────────────▼──────────────┐
   L3 地形感知  ←──  │ 高程图 / 可通行性 / 障碍物     │  10-30 Hz
                     └──────────────┬──────────────┘
                                    │ 地形高度、摩擦估计、落脚点
                     ┌──────────────▼──────────────┐
   L2 状态估计  ←──  │ IMU + 腿里程计 + 视觉/LiDAR   │  200-1000 Hz
                     └──────────────┬──────────────┘
                                    │ 机身位姿、速度、接触标志
                     ┌──────────────▼──────────────┐
   L1 运动控制  ←──  │ 步态/MPC/RL 策略 → 关节目标    │  50-500 Hz
                     └──────────────┬──────────────┘
                                    │ 关节位置/力矩
                     ┌──────────────▼──────────────┐
   L0 本体      ←──  │ 电机驱动器内环（力矩/电流）    │  1-10 kHz
                     └─────────────────────────────┘
```

**关键工程约束：越往下，延迟越致命。** 运控层多 10 ms 延迟，实机就会抖；导航层多 100 ms 基本无感。所以几乎所有「全栈性能问题」最终都归因到 L1/L2 的时序。

## 3. 范式演进（2018 → 2026）

| 年份 | 事件 | 意义 |
|---|---|---|
| 2018 | MIT Cheetah 3 的 convex MPC（Di Carlo 等，RA-L） | 把四足控制写成标准 QP，模型派巅峰 |
| 2019 | MIT Mini Cheetah 用 RL 直接学步态（Hwangbo 等，Science Robotics） | 证明「不建模也能走」，但还离不开仿真到现实的鸿沟 |
| 2021 | RMA（Rapid Motor Adaptation，RSS 2021） | teacher-student + 在线适应模块，成为后续所有 sim2real 的模板 |
| 2021 | legged_gym + Isaac Gym（Rudin 等，CoRL 2021） | 单卡 4096 环境并行，训练从「天」压缩到「分钟」，开源生态爆发 |
| 2022 | Walk These Ways（Margolis & Agrawal） | 一个策略条件化出多种步态，RL 开始「可控」 |
| 2023 | ANYmal 感知式鲁棒运动（Miki 等，Science Robotics） | 首次把外部感知接进 RL 策略，雪地/废墟级鲁棒性 |
| 2023 | DreamWaQ / Robot Parkour Learning | 隐式地形估计；跑酷进仿真→真机 |
| 2024 | Extreme Parkour（ICRA 2024）、HIMLoco | 极限运动能力；历史观测解决部分可观测 |
| 2024-2025 | IsaacLab 取代 Isaac Gym；OCS2 生态成熟 | 工具链换代，工程门槛继续下降 |
| 2025 | π0.5、GR00T N1、V-JEPA 2、Genie 3 相继发布 | 通用 VLA / 世界模型进入「可用」区间 |
| 2025 | MoRE（arXiv 2503.08007）、ODYSSEY（arXiv 2508.08240） | 四足上的 VLA + RL 混合开始有人做（ODYSSEY 是四足 + 机械臂的长程探索/操作），但仍是论文级 |
| 2026 | 世界模型增强的运动控制（如 arXiv 2609.02542）、产业整合 | 研究热点转向「用生成式模型补数据/补预测」，产品侧转向可靠性 |

### 3.1 三条主线的交替

1. **模型派（2018-2020）**：MPC + WBC，靠精确建模。优点是稳定、可解释；缺点是换个机器人就要重新调，且对地形/打滑极敏感。
2. **学习派（2021-2024）**：大规模并行 RL + 域随机化。优点是鲁棒、跨地形；缺点是训练贵、可解释性差、安全边界难保证。
3. **混合派（2024-2026）**：RL 策略作为「运动基元」，上层用 MPC/规划器给目标，或反过来用 MPC 提供先验。**现实中的工业方案几乎都是混合的**，纯 RL 或纯 MPC 都少见。

> 这条演进最重要的含义：**运动控制已经不是瓶颈了。** 2026 年做一只能在平地和常见台阶上稳定行走的狗，用开源栈几周就能搭出来。真正的差异化在上层——感知鲁棒性、长程任务、以及交付可靠性。

## 4. 「宣传」与「真机」的差距（本报告最重要的一节）

调研里最容易犯的错，是把论文 demo 当成产品能力。我们统一按四档标注：

| 档位 | 定义 | 典型例子 |
|---|---|---|
| **A. 真机常态化** | 在真实产品中持续运行，有客户交付 | Spot 的巡检、Unitree 的 SDK 运控、ANYmal 的工业巡检 |
| **B. 真机实验** | 真机上跑通，但是实验室/论文条件 | ANYmal 感知式运动、Extreme Parkour、各种 parkour 论文 |
| **C. 仿真验证** | 只在仿真/公开数据集上验证 | 大量 2025-2026 的 VLA 论文 |
| **D. Demo 视频** | 只有剪辑视频，无可复现细节 | 多数发布会上的「机器人管家」 |

按这个标准看 2025-2026 的现状：

- **L1-L4 基本都在 A/B 档**，这是可以放心选型的地带。
- **L5 的 VLA 绝大多数在 C/D 档。** 真在四足上做真机实验的（如 MoRE、ODYSSEY）也是 B 档：固定场景、有限任务、需要人工兜底。
- **世界模型在腿式机器人上的实际使用率极低**，主要用途是「生成训练数据」和「做预测的辅助 loss」，而不是直接当策略。

所以我们给出的选型建议是：**下层用成熟开源栈，上层保持可插拔架构**，不要把产品赌在 L5 的某个模型上。

## 5. 术语表（统一口径，避免各章说法不一）

| 术语 | 英文 | 含义 |
|---|---|---|
| 凸 MPC | convex MPC | 把四足控制近似成凸 QP，单次求解毫秒级 |
| 全身控制 | WBC (whole-body control) | 分层 QP，优先级处理任务与约束 |
| 腿里程计 | leg odometry | 用腿的运动学和接触状态估计机身位移 |
| 高程图 | elevation map | 把地形栅格化成高度图，供落脚规划 |
| 可通行性 | traversability | 地形能否通过的度量 |
| 域随机化 | domain randomization | 训练时随机化物理参数，缩小 sim2real gap |
| 教师-学生蒸馏 | teacher-student distillation | 特权信息训练教师，学生只用可观测信息 |
| 运动基元 | skill primitive | 可复用的底层运动技能，供上层调用 |
| VLA | vision-language-action | 视觉-语言-动作模型 |
| VLN | vision-language navigation | 视觉语言导航 |
| 世界模型 | world model | 预测未来观测/状态的生成式模型 |
